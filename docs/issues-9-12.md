# 新增需求 #9–#12：实现与人工验收

本轮对应 [#9](https://github.com/d8349565/MultiTool-Office-Next/issues/9)、[#10](https://github.com/d8349565/MultiTool-Office-Next/issues/10)、[#11](https://github.com/d8349565/MultiTool-Office-Next/issues/11)、[#12](https://github.com/d8349565/MultiTool-Office-Next/issues/12)，纳入 v0.5.0（应用构建版本 `2026.1022.1606`）。以下人工场景仍待用户验收。

## OCR 一键任务与自动配置

添加文件后，点击“一键完成”。识别配置默认采用“自动识别配置”，也可以固定选用具体配置；选择和一键任务选项在本机保存。

- 自动模式先识别首页，根据已有配置的非空、去重关键词计分。只采用达到各配置文字阈值的识别行；唯一最高分才继续按该配置的页范围、DPI 和区域提取。关键词分数不作为模型置信度。
- 无命中、并列或文字质量不足的文件保留文字，进入待复核，不生成拟命名。结果行中的“更换配置”可仅重新处理该文件，新任务保留原结果；无需重新处理其他成功文件。
- 默认终点是“结果核对”。展开“一键任务选项”可选择 TXT / CSV / JSON 自动导出及文件夹，或生成改名预览、自动改名正常项。
- 自动改名首次启用，或所用配置、命名规则、任务选项变化后，展示规则并确认。沿用原有文件身份预检、同名加序号、不覆盖、改名记录及撤销机制。需复核、有警告且未人工确认的项目不会自动改名；名称截断、非法字符替换等命名警告也会进入待复核。
- 后续步骤出错或中断时，“仅继续后续步骤”跳过 OCR、已导出的结果和已成功改名的项目，并根据最新复核结果及拟命名重新生成未执行项目的预览。识别失败或取消的文件另用“重试未完成项”处理；成功项不重复识别。
- 导出先于改名，默认文件名为 `OCR-任务ID.格式`。先写临时文件，完整写入后再发布；中断后通过已保存的内容校验值恢复成功记录。无法确认的已有文件保留，另加序号新建，不覆盖。导出表中的当前文件名反映导出当时的状态；最终改名状态以改名记录为准。
- 执行状态和每文件识别进度可见；取消保留已经完成的动作，不能撤回已写出的导出文件，已改名项目可从改名记录撤销。

人工验收（由用户自行准备并选择文件副本）：

- [ ] 混合批次中，不同文件自动采用不同配置；明确命中后无需额外点击继续提取。
- [ ] 无关键词、无命中、并列候选及低质量首页进入待复核；没有偷偷采用列表首项。
- [ ] 修改单文件配置后只生成该文件的新结果；删除配置后固定模式明确提示重新选择。
- [ ] 重启后保持配置模式和任务选项；旧任务及旧改名记录可继续查看。
- [ ] 默认一键任务停在结果核对；配置自动导出后一次启动可生成结果，并显示实际路径。
- [ ] 自动改名的首次确认、规则变化再确认、重复名称、文件被修改 / 占用、部分失败和撤销符合界面说明。
- [ ] 快速重复点击不建立重复任务；执行中取消后，成功项保留，未完成项可单独处理。
- [ ] 后续导出或改名失败后重试，不重复导出成功文件或再次修改已成功改名的文件。

## 跨层目录筛选

右上角“筛选目录”仅在当前工作根目录的索引内查询所有层级。输入不会改变导航；候选显示目录名及相对路径，悬停可查看完整路径。选定后定位到该目录，并限定文件搜索范围。目录列表本身保留祖先链。

- “包含子文件夹”、扩展名、修改时间及“文件路径包含”可与所选目录和文件关键词组合。没有目录条件时，文件关键词仍搜索全部工作目录并包含子文件夹。
- × 清空目录条件和候选文字，保留导航、文件关键词及其他文件条件。已有文件路径筛选移至“更多筛选”中，与目录条件分开。
- 使用方向键选择、Enter 定位、Esc 收起；候选输入防抖、过期查询丢弃，每页 40 项。索引进行中及部分目录索引失败均有提示。

人工验收：

- [ ] 浅层、深层、仅后代命中、相同目录名及长路径均可查找和区分；可使用 `/` 或 `\` 输入相对路径。
- [ ] 输入不跳转，选定后面包屑完整；清除不改变当前位置或其他搜索条件。
- [ ] 与文件关键词、扩展名、修改时间和子目录开关组合时，列表符合所示范围。
- [ ] 切换工作根目录、目录移动 / 删除、权限不足、空结果及索引未完成均有明确反馈。
- [ ] 大目录量下的候选分页、键盘操作及响应符合预期；未预先宣称性能数字。

## Ctrl+K 常用与最近访问

沿用 Ctrl+K 和全局 Ctrl+Shift+Space。优先展示用过的常用工具、最近访问的文件 / 目录，再提供工具及索引搜索。文件预览成功、打开、定位、目录导航及工具成功启动后更新记录；重复路径合并，本机最多保存 100 项。

- 文件和目录执行应用内定位；文件会跳到所在目录的正确页码并选中。为保证目标可见，此操作清除文件搜索条件，显示所在目录的直接文件。
- 工具执行启动，历史项关联当前工具 ID 和目标；目标改动后需重新选择。失效、越界、目标类型变化或尚未索引的文件给出提示。
- 支持上下键、Enter、Esc、单项移除和确认后清空。候选显示类型和路径；工具按使用频次优先，访问项按最近时间排序。显示数量设上限，可输入关键词缩小范围。

人工验收：

- [ ] 浏览目录、预览或打开文件、启动工具后，呼出面板能及时看到记录，重启后保留。
- [ ] 同名文件、目录和工具不会混淆；各项执行正确的定位或启动动作。
- [ ] 文件位于第 2 页及以后时，能定位到正确页并选中；重复定位同一文件仍能重新选中。
- [ ] 目标删除、移动、授权范围缩小、工具目标修改及启动失败时，面板明确提示并保留移除入口。
- [ ] 单项移除、清空确认、键盘操作及深浅主题符合预期。

## 验证边界

本轮仅执行前端 TypeScript / Vite 构建、Rust 静态检查（含测试目标编译）及差异检查。新增自动匹配和自动改名确认的回归用例，但未运行测试用例、模拟服务、桌面交互或真实 OCR。未读取用户业务数据，也未验证 OCR 准确率或大目录性能。浏览器演示不执行自动导出和改名。

静态检查入口：`npm.cmd run build`、`powershell -NoProfile -ExecutionPolicy Bypass -File scripts/windows.ps1 -Action check`。测试目标可使用项目现有 GNU 工具链执行 `cargo check --tests --locked --manifest-path src-tauri/Cargo.toml`，仅编译，不运行测试。
